# 静态资产预制能力（Higgsfield 方法）

## 职责边界

只完成视频生成前的静态资产工作：角色、服装/伤势状态、场景、关键道具、文字资产、反向机位和局部修图。

- 本模块负责静态资产，Seedance 视频时间轴由导演主入口与视频编译模块完成。
- 用户同时需要资产与视频提示词时，先完成当批资产计划与资产准备，再返回导演主流程编译；沿用项目已授权范围和确认策略，不因本模块的阶段交接重复索要确认。用户明确要求分阶段验收时在该点等待；重要身份或结构冲突尚未解决时先按下文处理。
- 生成平台与资产方法分开：用户指定平台时使用其实际可用入口；未指定时使用宿主真实可用图像工具，不为采用本方法强制转平台。当前能力缺失或用户选择无生图时，执行[02G 生图能力与文生交付](../../knowledge/02G_IMAGE_CAPABILITY_FALLBACK.md)：已确认无生图模式只交付文字资产规划与生图提示词，不执行或等待图像生成及图像压力测试，随后继续文生视频编译。未实际生成、查看或执行的验收如实标注。
- 默认使用中文说明和中文提示词；模型容易歧义的摄影、材质或构图词可保留必要英文。
- 平台入口、模型版本、分辨率、参考数量和价格可能变化。需要精确当前能力时，先读取 [HIGGSFIELD_ASSET_ROUTING.md](references/HIGGSFIELD_ASSET_ROUTING.md) 并联网核实官方页面。

## 静默工作流

### 1. 诊断任务

先确认：资产类型、后续镜头用途、目标入口、已有参考、必须锁定的维度、需要的状态和未来摄影机角度。参考图存在时先区分：

```text
直接可见并可锁定
仅能推断、必须用文字补全
素材未显示、不能声称已确认
```

若图片与剧情冲突，先询问用户选择：保留图片并改剧情描述，或保留剧情并重新生成资产。

### 2. 按任务路由

用宿主真实可用的图像工具，按任务选能力，不按模型名：

- **角色照片/角色板**：选身份稳定、皮肤和服装细节可靠的生成入口；需要跨生成持久身份时用入口真实提供的身份功能，不用文字冒充。
- **场景、环境板、带角色的电影帧**：电影风格主要放在场景资产和后续镜头，不污染中性角色身份板。
- **道具、包装、画内准确文字**：选擅长产品结构和文字的图像或编辑模型。
- **已有图局部修改**：原图为唯一底图，每次只改一个可验收变量。
- **反向机位/新视角**：先建立同一场景的世界拓扑和新机位物件排列，再生成；不能只写“生成反面”。

用户指定 Higgsfield 时，Soul Cast、Soul 2.0、Soul ID、Soul Cinema 等入口的分工见 [HIGGSFIELD_ASSET_ROUTING.md](references/HIGGSFIELD_ASSET_ROUTING.md)。

### 3. 建立资产卡

每项资产都生成一张可复用资产卡：

```text
资产名
叙事用途
参考素材及其控制维度
身份/结构描述词
当前状态版本
生成提示词
界面参数
压力测试要求
```

同一项目的资产名、状态名和引用名保持一致。已进入图像资产路线的角色、场景、道具使用“稳定文字描述 + 对应图片”的双锚点；直接文生的场景由文字维持空间基线，不因本条补图。图片未显示的背面、比例、拓扑或动作事实仍须由已有证据或明确设计补足。

## 角色资产

### 剧情适配与身份区分

是否需要人物图由[02A](../../knowledge/02A_PROJECT_WORKFLOW.md)判断；本节执行已选择的单人或多人形式。先查人物本身及所属群演组的实际资产，已确认身份直接复用。缺失配角从剧情的时代、工作/生活场景、年龄线索、服装和表演用途补未定外观，设计选择记入资产卡，不改剧情关系，也不以职业或性格推定固定面相。

新独立演员与已有演员、同批群演在脸型/骨相、眉眼鼻口组合、年龄感、发际与发型、体态等维度形成可见区别；换衣服或换发色本身不算不同身份。只参考已知演员做差异比对，生成新人物时不把另一角色板作为身份母图、默认Soul ID或混合身份来源。主角和配角同框时，分别使用各自的图像职责。剧情明确的亲属相貌、双胞胎、同一人分饰或用户相似要求优先，不强行破坏该关系。

### 中性身份板

本节统一维护单人角色板生成与验收标准。调用方传入角色事实、已有资产、状态和用户版式要求；多人群演使用下节形式，不把不同人物塞进同一角色的三视图。用户明确要求覆盖对应默认。

- 先查看并复用已提供、绑定或验收过的角色资产。可用单图或其他版式不因新默认被替换；缺脸部、服装、全身或背面证据时只补所需维度，以已有身份和已确认服装为保护基线，保留原图。
- 新生成角色板默认采用“左侧大头照（轻微三分之四或用户指定正面），右侧依次并排正面全身、背面全身”。左半区为一幅足够大的头像；右半区分成两个竖向列区，左列正面全身、右列背面全身。共三个视图，都是同一角色；用户指定其他布局时按其要求。
- 头像保留完整发型、头顶、下颌与必要肩颈，眼睛平视且五官可读，表情中性自然。正面和背面全身均从头顶到鞋底完整入画并留边，直立姿态让衣服轮廓、手与双脚清楚；两幅全身保持同一人物尺度、身体比例、头顶线和地面线。
- 三视图身份、年龄感、脸型、肤色、发型、身材与同套服装一致；服装前后结构、后领、腰线、袖型、鞋型、配饰数量、材质和左右归属对应。具体设计来自当前角色设定与已确认参考，不由版式补造身份或穿着事实。
- 使用干净中性灰背景或用户指定背景色、柔和均匀且可读的光线、真实皮肤和材料；保留自然眼部反光、服装结构与完整肢体。身份板不预埋强烈电影调色、镜头畸变、极浅景深、运动模糊或剧情场景光。选择足以容纳三视图的横向画布，尺寸按当前生成入口能力确定，不以视频画幅硬裁角色板；不自动添加标签、水印或文字说明。
- 实际生成后查看结果，核对生效版式、同人同服同尺度、前后结构、面部可读性、手脚完整和背景清洁；与本模块的角色表演可用性及压力测试门合并执行，不把一张静态板的检查写成全部角度或动作都已验证。失败时按局部修改协议修问题视图或缺失维度，保留正确身份，不为换版式反复重生整套。仅有提示词不算已生成，未执行的验收不标通过。
- 如果模型在全景中反复误取全身小人脸，可将面部身份集中到大尺寸肖像，并裁切、遮蔽或弱化全身板中无法提供有效身份信息的小脸；这是一项失败修复，不是所有角色板的固定版式。
- 已知且有助于身份辨识时可写成年年龄段，例如“35岁成年男性”；未明确成年时不自行填写精确年龄。
- 真人身份、虚构人物、Soul Cast 和 Soul ID 的用途不同，不声称普通参考图具有持久训练身份的能力。

### 多人群演半身资产

用于已判定需辨清面孔、当前控制目标主要为面容和上半身的多人群演；单独承担表演或确需全身/背面证据的人物仍用单人板。本形式与单人板共用中性光、真实皮肤/服装、状态拆分和真实结果验收标准，差别是“一图多个独立身份”，不是同一人的多视图。

- 按镜头实际所需人数与身份类型生成，半身取景自完整头顶至腰部附近。可横向排开或采用清楚分区，各人脸部足够大、五官清楚、相互不遮挡，保留肩颈、发型与可见服装。自然中性表情、均匀光、可读景深，画面不附姓名标签或编号；位置映射在台账维护。
- 先给每名成员独立的脸型、五官结构、年龄感、发型及服装描述，再统一时代和群体用途；同组成员不能成为换装复制脸。人数以当前工具成图中面部可读性为限，过密或糊脸就分组，不硬塞全部人物到一张图；无需给面部不可辨的街道远景人群逐人补图。
- 实际查看后核对人数、每名成员的完整面孔、相互区别、与现有演员的区别、衣物归属和无融合/重复身份；将实际位置逐个绑定成员短名。只有失真或相似的成员需要修复时保留其他正确身份，修复后重新核对受影响映射。
- 后续需要更清晰特写、单独表演或未显示的身体/服装时，按[02B](../../knowledge/02B_CHARACTER_BOARD.md)从该成员实际区域继续身份，不随机重建另一张脸。半身图未显示的维度保留未验证状态；静态组板通过不等于多人视频或跨镜一致性已经验证。

### 匿名类型群像（补充）

无需个体身份的群众（路人、村民、看客）可做类型群像图：每张四到六人，单排完整全身，背景干净（灰底或项目约定），自然身高差、互不遮挡；人数多就分组，不给百人场面逐人做板。图里展示同一时代、同一生活环境中衣着、年龄、性别、体型的差异。视频里只借服装风格，五官随机为不同陌生人（绑定写法见 [02B](../../knowledge/02B_CHARACTER_BOARD.md)）。剧情要求同一个人再次开口、连续说几句或之后要被认出时，即使没名字也另做单人资产；这时群像里的随机脸不能代替单人依据。

### 状态拆分

湿身、受伤、血迹、换装、显著变形、昼夜、雨雪等会改变外观解释的状态，应建立独立版本：

```text
角色A_基础
角色A_雨湿
角色A_受伤
角色A_换装2
```

每个版本只包含该状态真实存在的变化，不把未来伤势或其他服装混进基础资产。

### 表演可用性

人物资产先通过其单人/多人形式的身份、服装、结构、差异与可读性检查。正侧转头、睁闭眼、张口说话、抬手、坐姿、全身运动和与另一角色同框均为可用性测试维度，按当前及已计划镜头的实际用途覆盖对应项；只交静态板时不强制额外生成无用途的动作或同框测试。未覆盖项记录为未测试，不据此宣称所有表演都可用。眼睛保留自然湿润感与可见 catchlight，但不把强情绪固定进中性身份板。

## 场景资产

本节维护已需要的场景图制作与同空间验收；是否出图及需要哪些方向由[02A场景决策](../../knowledge/02A_PROJECT_WORKFLOW.md)先确定。独立请求指定场景图时，按其明确范围执行。A代表所需基准方向，B代表确需补充的反打方向；只需A的任务以单图完成，文生场景和文字反打不进入缺图清单。只有需要A/B时才执行下面的双向一致性检查，更多角度仍按实际用途准备。

### 生成与复用顺序

1. **先定同一空间与所需方向。**查看实际相关图，建立稳定地标、彼此方位与距离、门窗/通道、入口出口、危险线及光源位置。仅为所需方向写机位、朝向、可见区域及地标投影；原图未显示的区域按已确认拓扑和剧情补齐，在资产卡区分参考可见事实与设计补全。
2. **先复用，缺图只补当前必要方向。**已有A满足用途就保留A，不自动补B；已有适用的A/B分别复用，不因命名不同重生。新增或补充场景先生成必要的基准方向，查看并修正结构；若是母场景的补充区域，先继承母场景拓扑。当前只需单向，到此即可完成。
3. **确需B时再由真实A派生。**实际传入已确认的A给支持参考生成/编辑的工具，生成反打方向；B继承同一空间。A/B可以是入口朝内与内部回看、沿街两端或庭院两侧等相对方向，不强制入口/内部命名。两张独立随机图不能仅凭风格相似认作同一空间。
4. **换机位，重算投影。**无论B图还是文字反打，都继承世界拓扑、尺度、材质与光源，按新机位重算 `screen-left/right`、前中后景、遮挡与明暗。B不能是A的镜像或原构图换色；文字反打按同一规则写真实另一侧，不因缺B复制A的背景。
5. **改编项目以原片帧为底图。**改编自已有影像（动画、剧集）的项目，复用场景以原片对应帧为底图转成本项目画风，保留原片布局和陈设。新场景图里出现已有场景的东西（门、窗、柜子、同一条街）时，把已有场景图和已验收成片的截帧一起作参考；生成后先和已有图核对，再用。

### 需要双向图时的同空间与方向辨识

- 门、窗、柱、壁炉、祭坛等关键元素保持同一实体、数量、世界位置及连接关系。通过观察方向、可见面、遮挡和真实另一侧背景形成辨识度；不为了让两向都“有标志物”把原有独有元素复制、搬到对墙或凭空增添第二套。也不为避免画面重复而删除实际应当可见的同一元素。
- 允许同一个地标从两向出现，这正是空间接续证据；用它的另一面、连续地面/顶面纹理、相邻固定结构或连通关系确认同一空间，不强求所有关键元素在两图都入画。例如北墙唯一壁炉在A中正面可见，B从北侧回看南向时通常在机后或边缘，不应在南墙再造一个；同一根中柱可在两图出现不同侧面。
- 两图采用同一状态版本与光源逻辑，机位变化可以改变画面内光的来向、遮挡和阴影投影。昼夜、天气、损坏等确需改变时另立状态，不能拿不同状态或另一空间凑成一对。
- 生成后对照查看A/B，核对机位/朝向确实相对、地标唯一性、门窗通道连通、尺度、材质、光源和遮挡是否成立，且两个方向可区分。问题集中修复缺失或错误方向，保留正确图；未查看两图不标记“成对可用”。

资产卡只登记实际需要的方向、机位、真实文件与验收状态；有B时记录其所依据的A。单向可记“该方向可用”，只有已查看并核对两图才记“成对可用”；未请求的方向不标待补。视频按当前镜头需要选择真实参考，图像控制固定拓扑/材质，动态编译沿[03场景投影](../../knowledge/03_VISUAL_GRAMMAR_AND_SCENE_ROUTER.md)；资产有两张也不一律绑定两张。

已确认无生图时，只交付已判定需要的方向提示词与拓扑。确需B且有真实A时写其参考关系；尚无A时，把先生成并查看A、再据其校准B列为待执行依赖。直接文生的方向不额外建资产提示词。依02G继续视频文字编译，计划名不冒充真实附件或已完成的图像验收。

只有已需要B且缺少直接反向机位工具时，才可在当前授权与实际工具范围内，以A为基准生成空场景缓慢穿行视频，从可用反向角度截帧并修整，仍核对同空间关系。截帧只是新视角证据，不自动成为角色首帧；无法取得时如实保留该项缺口，不用另一空间替代。没有B图任务时不启动此替代流程。

### 场景补充

- 反打是把机位移到对面并转向，写清相机在哪、朝哪、看见哪面墙、原来什么在相机身后；左右翻转原图不是反打。
- 每个机位一张图，不用多宫格冒充可以直接绑定的独立角度。
- 剧情真有门内外、院内外、屋与走廊这类连接时，按需要分别覆盖：整体关系的斜俯拍母图、从外看门、从内越门看外、从入口纵深看到目标。只补剧情用得上的，不给每个地点机械配齐。
- 夜景从对应日景改图，保留构图、门窗和陈设；灯在空间里位置固定，记下哪盏亮、什么颜色、照到哪，反打时同一盏灯在另一侧也要对得上。
- 会被拿起、带走、交接的剧情道具不预先画进场景图，由道具图和文字在视频里放位置；只作布景、本段不动的家具保留在场景里。
- 用户说场景“不要太多细节”时，默认指弱化细碎纹理（木纹细线、划痕、油渍、墙面颗粒），不是删掉生活物件。改场景图时以上一版为底图，只改光影、质感和氛围，物件保留。

## 道具与文字资产

- 关键道具提供正、侧、背、顶部和必要结构视图；锁定尺寸、材质、磨损、功能面、握持点和状态版本。
- 准确文字写出完整内容、字体类别、字重、颜色、表面和位置；文字仍应单独验收，不假设一次生成必然正确。
- 品牌或受保护设计只有在用户有权使用且明确要求时才保留；否则使用功能、材料和造型描述。
- 复杂手势（手指框、手语、特定指位）在前景或虚焦时，做一张灰底手势参考图：只有手，手的数量、指位和朝向画清楚，按道具图方式绑定。视频里写明画面里只有两只手，手势只轻微虚焦。

### 道具补充

- 是否单独做道具图看使用频次和叙事作用：反复出现、承担揭示或身份凭证、需要读清文字的物件，即使只出现一次也做；普通小物短暂出现一次就随镜头文字生成。
- 同场同位置一起用的物件（一桌早餐、一套工具）可以连各自盛器做成一张组合道具图；绑定时写明本段取用组里的哪一件，不默认整组入画。组合过密导致关键物件或文字看不清时再拆。
- 附着在门、墙、桌上的道具做带环境定位线索的近景；门上的东西随门动，不跑到墙上。
- 信息型道具（信件、票据、海报、证件）出图后实际核对每个字、数字和数量，错了不能靠文件名掩盖。

### 车辆补充

- 需要保持身份的车辆按关键道具做多视图，一个视角一张图，不用多宫格：前3/4、后3/4、正侧（驾驶侧）为基础；镜头会用到时再补正前、正后、驾驶位内饰、轮毂或车灯特写。
- 每张都锁同一组身份：车身类型与比例、颜色与漆面类型、轮毂样式、改装件、车灯造型、左舵或右舵。正侧图明确是驾驶侧还是副驾侧，文件名和资产卡同步写。
- 身份图用均匀柔和的环境光、干净背景、四轮接地有接触阴影，车轮回正、车门关闭；夜景、雨天、泥泞、损伤等做成状态版本，从身份图改图，不另起一台车。
- 车牌、车标按画内文字处理；没有授权的品牌车型改用造型与比例描述，规则同上方“品牌或受保护设计”。
- 视频里的车辆写法、车身左右和反射规则见 [05G 车辆影像](../../knowledge/05G_VEHICLE_CINEMA.md)。

### 审片表（补充）

出图后逐项看真图、写一句看到了什么（PASS 和 FAIL 都要写），不写“挺好”“不行”：

| 项 | 看什么 |
| --- | --- |
| 意图 | 要画的那件事画出来没有 |
| 构图主次 | 一眼先看到的是不是主体，有没有东西抢戏 |
| 人物动作 | 动作、视线、表情是不是要求的样子 |
| 手脚结构 | 手指数量、关节方向、四肢比例、手里的东西握没握住 |
| 光影 | 亮面和影子是否来自同一组光，有没有凭空的亮光 |
| 质感 | 皮肤、布料、金属各有各的样子；画是同一种画法 |
| 空间与接触 | 透视统一，脚踩地、物放桌有接触阴影 |
| 伪影 | 重复的东西、融在一起的物体、乱码、怪纹理 |
| 同一人／物 | 有参考图时是不是同一个人、同一件东西 |
| 文字 | 每个字对不对 |
| 系列一致 | 多张图之间人、衣服、道具是否一致 |

不适用的项写“不适用”。比较两种写法时可做 A/B 盲评：同模型同尺寸各出一张，匿名成 A、B，评完再揭晓。

## 局部修改协议

一次修改只改变一个可验收目标：

```text
修改目标：当前要改变的唯一事实。
变化区域：对象、位置、形状、材质和完成状态。
保持项：身份、服装其余部分、姿态、场景拓扑、机位、光线、色彩和其他已验收细节。
```

删除物体时同时写出缺口由什么真实表面填补。避免让整张已验收图反复通过生成模型；局部变化可通过遮罩合回原图，以减少身份、纹理和色彩漂移。

## 压力测试门

资产锁定前，覆盖当前及已计划用途需要的角度、姿态、光线和同框关系；广泛复用资产时相应扩展覆盖。只需静态板或局部修图时，完成该范围检查并保留未测维度，不把全部测试库变成每次交付的必经步骤。高要求项目可以把多次生成全部可辨认作为基准，不机械规定次数。已确认无生图模式仍按02G停在提示词交付，不启动这些图像测试。

以下失败仅针对当前实际需要并绑定的图像资产：先修受影响资产，不放行依赖它的镜头。文生场景、文字反打及未请求的B不属于未完成的图像验收项：

- 角度变化后身份或服装主体结构漂移。
- 与第二角色同框后脸、身材或服装互相污染。
- 场景换机位后地标、入口出口或左右拓扑无法成立。
- 道具在不同视图中尺寸、结构、文字或功能面改变。
- 局部修改破坏未要求改变的身份、机位、光线或材质。

## 输出格式

单项资产默认输出：

```text
【任务与模型】
【参考素材与控制维度】
【资产提示词】
【界面参数】
【验收清单】
```

多项资产先输出资产清单和状态拆分，再逐项给提示词。界面参数与提示词正文分开；不要把模型名、分辨率按钮或不可用的参数伪装成画面内容。

图片里碎纹、斑点、锐化痕迹多时，资产提示词加一段画质：画面干净通透，细节克制有层次，主体清晰，背景适度简化，大面积材质连续，减少无意义碎纹和斑点，远景以轮廓和体量为主，低噪点。
