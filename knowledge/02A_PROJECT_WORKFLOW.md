# 02A Project Workflow

scope: 新编/计划续编的工程盘点、资产准备与分批交付；不扩大 micro/local 范围。

## 新编项目的目录、资产与分批交付

本节用于新编、整集编译和按计划继续编译；版本先沿 SKILL 入口解析。用户的明确目录、批量、时长、素材与画幅要求覆盖以下默认。`micro/local`修复只更新目标提示词和必要台账/索引条目，不重建目录、不重读全项目、不自动批量补图。

### 先盘点，再建立工程

沿入口已选择的 `workspace_mode` 执行；飞书协作先按[02H云端资产工作区](02H_FEISHU_ASSET_WORKSPACE.md)读取对应项目的当前采用剧本、资产和段落记录，把当前需要的真实附件下载到本地项目，再与本地文件合并盘点。云端查询未完成或权限失败不等于资产不存在。已配置项目只检查当前连接，不重新部署；本地模式不加载飞书配置。

先定位用户指定项目，读取已有总索引、当前剧本范围、资产清单、光影运镜规则和音色绑定。用文件检索找到已有角色、场景、道具和屏幕画面图，实际查看本次相关图片，再判断可复用性；文件名不是内容证据。沿用用户选定或验收过的身份、外观、拓扑与音色，不因新增默认而替换它们。

在可写项目根目录或已有制作输出根目录下，默认实际创建并维护以下结构；已有同职能目录（如“场景资产”“道具资产”）原位复用，由索引映射，不搬迁、改名或重复生图：

```text
00_总目录索引.md
资产图/                 # 需要补图时可按角色、场景、道具细分
提示词/                 # 第01段_场景功能.md；一文件一独立段
制作台账/
  制作台账.md           # 规则、资产职责、分段计划、连续性与交付状态
  参考片理解/           # 有参考片时才建立：本地视频、抽帧和理解笔记
导演项目层/             # 项目规则、lint补充、事故日志、编译卡；可映射到已有台账目录，见02K
```

不覆写无关现有文件；按当前工程命名续接。没有文件工具/可写项目位置时，按实际能力交付目录清单、索引正文与当批提示词，明确哪些文件尚未落盘，不声称已创建。用户仅要求聊天内提示词或明确不要文件时，遵循该范围。

索引至少列出：目标版本、总时长上限与已规划总时长、目录入口、全局分段表（段号/剧情功能/准确计划秒数/所需资产/提示词链接/状态）、当前批次与下次起始段。未编译段标为“待编译”，不得提供伪造的已完成文件链接。台账记录已有/待补/文字锁定资产及路径、使用段号、控制维度、参考片证据、IN/OUT、声线来源和用户覆盖。区分“已编译/已交付/用户已验收提示词/成片已验收”，不把发送、沉默或“继续”记成成片验收。

### 项目层、规则分层与差分核对

- 开工时按 [02K项目层插槽](02K_PROJECT_SLOT.md) 建好或登记项目层，并在总索引顶部写“开工先读”路由：本 Skill 核心卡、项目规则、声线/角色规则、当集台账、分段表、剧本与最新交接、编译卡目录。
- 规则分三层：Skill（通用，随版本发布）→ 项目层（本作品规则与决策）→ 当集台账（这一集的特例）。用户新定的规则先写项目层；新事故改写成项目层里对应 A–F 分组的一条，不在当集台账平铺追加。
- 每集收尾时把当集台账里仍通用的条目上移到项目层，当集台账只留分段计划、资产台账和这一集的特例。
- 状态事件链（补充）：在项目层维护 `对象｜原状态｜变化事件及位置｜新状态｜结束依据｜对应图片或缺口`，换装、受伤、包扎、湿身、污渍、道具转手按发生点往后推进，切镜、换场、换集本身不算恢复；区分身体状态和当时看得见的状态（伤被衣物遮住就不露）。
- 资产反查（补充）：从剧本里的发言、动作、识别和状态变化倒查，每个动作需要的实体都要有着落（脱帽要有帽、贴封条要有封条、塞进马甲要有那件东西）；已有文件齐全不等于清单没有漏项。
- 两段一批时，第二段开场按第一段计划结尾写成“暂定开场”；第一段出片后先做差分核对（实际结尾与暂定开场逐项比对：人、位置、朝向、手持物、台词进度），不符就在第二段未生成前原地改，并换成第一段实际尾段作衔接。

### 风格规则只选一个生效来源

沿入口已确认的“用户规则 / 库内选择 / 新反推”来源执行，已明确的选择不重复问。当前用户提供的规则优先；要求从对标视频/链接新反推时，按 [styles/STYLE_ROUTER.md](styles/STYLE_ROUTER.md) 完整进入内置规则反推功能，待规则文件真实完成后作为同优先级的当前用户规则读取，再返回本项目编译。缺少对标视频时询问目标，不静默改选库内。若用户未改变来源，沿用当前项目已确认规则；没有用户/项目规则且未要求新反推时，才按类型目录选唯一最合适包。确认采用哪套光影运镜规则（库内包、用户文件或新反推结果）后，把它提取为项目层里单独存放的规则文件，后续批次读这一份；`style_source` 与该文件路径记在 `项目规则.md` 的 Resolved Policy（见[02K](02K_PROJECT_SLOT.md)）。制作台账可另记某批实际用的是哪套。摄影/表演方法服务当前故事，文件名称不成为角色或剧情来源。

### 先全局分段，再准备当批资产

按当前授权剧本范围先建立全局分段计划：保留完整因果与台词，估算对白、串行动作、必要读取/反应和OUT，遵守用户总时长上限，并采用入口已解析版本与06的时长默认。先解决段尾短碎、跨段关系和资产复用，再写当批完整提示词；索引规划全部段落不等于提前编译全部段落。用户只指定局部范围时，不扩读未授权的后续剧本。

这里的“跨段”指跨至少两个独立生成请求，同段多个CUT不算跨段。按全局计划统计复用，不因某资产只在当前批出现一次而漏判；需要新增资产时先准备当前批所依赖的缺口，后续专用资产可待相应批次再生成。

先分别完成下面的场景与人物资产判定；只有确实需要新增或修订图像资产，才以 [02F_HIGGSFIELD_ASSET_PREPRODUCTION.md](02F_HIGGSFIELD_ASSET_PREPRODUCTION.md) 路由的内置资产预制功能作为规划、状态拆分、参考控制与验收标准，不以用户是否说出“Higgsfield”为触发条件。只准备当前授权范围与当批镜头实际需要的资产和角度，已有可用资产继续复用。用户的文字锁定、不生图等范围约束仍优先，micro/local不因采用预制标准而扩大修改范围。

场景出图决策只在此处维护，按以下优先级执行：

1. **文生优先。**短暂出现、不跨独立生成请求复用的场景，直接用文字建立空间；同段多个CUT、一次反打或存在A/B字段都不构成出图理由。跨段复用也只是进入必要性判定：稳定文字已能表达所需布局、材质与变化时，继续文生。原先文生的场景不进入缺图队列，也不为它配置生图接口或额外交付场景生图提示词。
2. **必要图按方向准备。**复用场景若有需保持的特定布局/视觉设计，且文字不足以稳定表达，或实际结果已显示漂移，才为当前所需方向准备图像；先查已有合适图，再补真正缺口。台账简记复用段、所需方向和出图依据。已有单向图可满足当前用途，缺B不等于资产不完整。改编自已有影像的项目，复用场景以原片对应帧为底图，做法见内置资产预制的“生成与复用顺序”。
3. **反打单独判定。**仅当已规划的反打方向本身要跨独立请求复用、且确需图像参考时，才进入B图生成；场景A复用不能替代反打方向复用的证据。一次性反打或文字足够的反打，按同一拓扑从新机位重建文字画面，不补B，也不等待B。需要B时再经02F从真实A图派生，按同空间标准验收。

用户明确要求指定场景图或“生成所有场景”时，覆盖上述默认出图范围；全场景只表示覆盖全部指定场景，不自动要求每场景两个方向。只有明确要求所有A/B或指定反打图时，才按所要求方向准备。未要求的方向继续按需判定，原有已验收图片保留。

人物出图决策与场景分开，按当前及已规划镜头中的辨识需求判断，不按是否具名或复用次数判断：

- **可辨配角优先资产。**承担需单独跟踪的剧情行动、对白/互动、身份连续性，或镜头能辨清面孔的配角/群众，先查该人物自身的适用资产；缺失时结合剧情的时代、职业、年龄线索、服装与镜头用途准备人物图。单次短暂出场也不自动降为文生，更不借主角或另一角色的脸来填缺口。仅补未定外观设计，已定身份、关系和剧情事实不变。
- **按用途选择形式。**单独承担表演或需要全身/背面证据的人物，沿02B制作单人中性角色板；以面孔与上半身为控制目标的多人群演，可一次生成多人半身资产，成员各有清楚且不同的脸。具体版式、身份差异与验收只由内置资产功能维护。后续成员被单独跟拍、特写或需要未覆盖的身体/服装证据时，沿其已生成身份补足，不能重新选脸。
- **不可辨背景群像优先文生。**街道远景、背影、剪影、虚焦人群等在当前及已规划用途均无需辨认个体，直接写人群密度、层级、流向与动态，不建立逐人角色板。街道只是场景类型：近景行人能辨脸或要接续同一人时仍回上两条。已有主角板只控制主角，背景群众维持独立身份；确有换装分饰或相貌关联时按用户/剧情明确设定处理。
- **匿名类型群像（补充）。**中近景里看得见脸、但不需要认出某一个人的群众（围观街坊、集市路人），需要统一时代和生活环境的衣着时，可做类型群像图，绑定写五官随机生成不同的陌生人（版式见内置资产预制，绑定见[02B](02B_CHARACTER_BOARD.md)）；远景、背影、虚焦仍文生，要再开口或之后被认出的人回到第一条做单人资产。

下表的实际生图默认适用于图像能力可用的路线。能力缺失或用户确认无生图时，按 [02G_IMAGE_CAPABILITY_FALLBACK.md](02G_IMAGE_CAPABILITY_FALLBACK.md) 处理接口建议、资产生图提示词与文生交付；本表不重新开启已确认的选择。

| 对象与使用方式 | 默认处理 |
| --- | --- |
| 已有可用且与剧情一致的图像资产 | 复用当前实际需要的文件；只补已确认必要的状态或控制维度，不整套重生；场景不因存有A图而自动补B或强制绑定所有旧图 |
| 按上述人物决策缺少资产的角色、可辨配角或群演 | 经[02B_CHARACTER_BOARD.md](02B_CHARACTER_BOARD.md)交接单人板或多人半身形式，由02F调用内置标准实际生成；已有身份与服装为保护基线，用户指定文字锁定时跳过 |
| 无需辨认个体的远景/虚焦/背影群像 | 默认文生，保留群体空间与动态锚点，不创建逐人图片依赖 |
| 非复用/短暂场景，或文字足以表达的复用场景与反打 | 默认直接文字编译；保持空间基线，不创建图片依赖 |
| 按上述决策确需场景图的方向，或用户明确指定出图 | 经02F准备实际所需方向；只需A就交A，B按独立判定补充。图像控制固定拓扑/材质，当前动态仍由CUT建立 |
| 跨独立段复用、需要保持外观的道具，缺少可用图 | 实际生成道具资产图，锁轮廓、结构、材质、颜色及必要功能面 |
| 不跨段复用的道具 | 允许直接文字编译 |
| 用户明确指定某复用物件用文字锁定 | 文字锁定优先；每个相关段完整重申相同身份/外观与当前状态，不再生图 |

预制方法标准与生成平台分别决定：模型、工具与参数按用户指定和宿主真实可用入口执行，遵守对应调用规则；采用02F标准不要求购买服务或切换到Higgsfield平台。以资产计划、状态版本和验收要求驱动实际生图/修图，再真实查看结果，核对拓扑、结构、身份和当前用途；新图保存或复制到项目对应资产目录并登记实际路径，原素材保留原位。“已写生图提示词”不等于“已生成图”，“已生成图”也不等于资产已经验收可用。工具不可用或失败时记录具体缺口，继续不依赖该图的工作；尚未解除的图像依赖保留待补资产草稿，已确认无生图模式按02G完成文生交付。用户已授权生图的范围不重复索要确认。

### 向02F交接并接回资产

资产交接的输入与返回清单只在本节维护，02F与02B指向这里。传入项目路径、当批段号与镜头用途、资产名/类型、已有图片及声线绑定、身份/服装/结构/拓扑保护项、所需状态版本、新角度或局部变化目标、用户指定平台/模型与真实可用工具、`asset_mode`（默认 `image`；已确认无生图为 `text-only-confirmed`，见02G）和已授权范围，用户明确覆盖项一并传入。场景另传已选文生/图像、所需方向及复用依据、用户指定出图范围。人物另传锁定名/稳定ID、剧情职能与时代服装线索、当前及已规划镜头的辨识与身体覆盖需求、单人/多人形式、需区别的已有演员外观与用户版式要求，由02F读取内置人物资产标准；02B只负责人物登记与视频绑定，不维护另一份版式或验收细则。

02F完成后回传实际资产文件路径、对应提示词/必要界面参数、控制维度、状态版本（场景含实际方向）、已执行的检查/压力测试结果、未覆盖的角度或表现和未解决缺口。本流程据此登记索引与台账，区分仅计划、仅提示词、已生成、可用和用户已验收。图像路线在当前用途所需资产可用后才把依赖段标为可提交生成；已确认无生图路线采用02G的文字锁定、文件与状态合同，随后返回原视频编译范围。完整资产功能在02F所指的包内位置维护，本文件不重复模型表和验收细则。

飞书模式在新增资产落盘并检查后主动按02H上传图片及其生图提示词，批次交付时同步段落提示词和总索引；micro/local仅同步实际受影响文件。云端“用户上传视频”字段由用户维护，按02H保留；同步结果与本地交付结果分别登记，失败进入待同步队列，不把传输失败当作需要重新生成资产。

资产图画幅服务其用途与项目构图，不强制21:9。场景图清楚展示需复用的空间关系，静态道具图清楚展示结构；视频中的浅景深默认不套到这些证明结构的资产图上。角色与声线先沿用已绑定素材，不因本流程机械增生新角色图或新音色。可读屏幕/新闻/UI若需要稳定内容，按剧情确认完整画面与文字后可单独生成屏内画面资产；分别限定内容贴图与屏幕所在场景的控制权，不能只靠“无乱码”一句代替内容锁定。

### 用户参考片：先区分风格反推与事实证据

用于对标光影、运镜、构图、表演、声音或整体拍法的参考片/链接，先沿 [STYLE_ROUTER](styles/STYLE_ROUTER.md) 执行内置光影运镜表演规则反推功能，以完成的规则文件返回导演编译；不在本模块用关键帧抽样另写一套反推流程。仅用于故事事实、动作状态或素材职责核实时加载 [02E_MEDIA_EVIDENCE.md](02E_MEDIA_EVIDENCE.md)，实际成片/尾帧续接同时按 [02C_CONTINUATION_REFERENCES.md](02C_CONTINUATION_REFERENCES.md)。用户只反推规则时停在规则文件交付，不启动视频编译确认或本工程分批编译。

### 默认每次只交付两段

编译前在已有Resolved Policy中分开记录“全局计划段号”和“本次交付段号”：默认从下一未交付段取连续2段。“共3段”“60秒，已有3段计划”或粘贴全部分段大纲只限定全局；“本次输出3段”“交付第3至5段”“一次全部输出”才覆盖当前批次。纯提示词、无文件、review_mode=off不改变批次边界。在同一次交付预检中核对实际段标题与本次段号一致，到达批次末段即停止，不再起下一段标题。

每次只编译并交付当前未交付的连续2段；只剩1段则交付1段。用户指定数量或段号时覆盖默认，“下3段”即当前批3段，不反复确认；“整集开始编译”默认仍先规划整集、交付首2段，明确要求一次全部交付才输出全部。到达当批范围即结束，等待用户反馈或继续指令，不后台写完后续提示词。

每个提示词文件只包含“段标题+五栏”，文件管理、理解来源和检查记录放在索引/台账。工程模式交付时，在提示词之外给用户一张“镜头｜画面内容｜作用”表（每个CUT一行，作用写这一镜在戏里承担什么），附编译卡的方位要点、自检结论和已知风险；用户是新手时，术语第一次出现附一句白话（如“拉镜头（机器慢慢远离）”）。工程模式可在候选外提供当前批文件和总索引的简短链接；提示词-only模式只给当前批纯提示词。交付前在同一次预检中核对当前批实际文件、资产路径、索引链接/状态与总时长，无需新增审核轮次。冷审若触发仍一包一段，批次大小与冷审单位分开；只有用户明确要求逐段验收才在批内逐段等待。

用户说“继续/下两段”时从索引下一未交付段续编，只载入稳定锚点和必要相邻IN/OUT。尚未生成视频的计划编译沿用草稿边界，不要求不存在的成片；明确依据实际成片续写或修尾时，才核对已接受视频/尾帧或用户提供的真实结尾。用户修正已交付段时只修指定段及必要接力，不顺带再交付新的两段。
