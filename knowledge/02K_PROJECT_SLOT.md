# 02K Project Slot

priority: high
scope: 项目层插槽约定。项目特有的规则、决策、检查和事故记录放在用户项目目录里，每次编译读取；Skill 本身不随项目改写，所有用户共用同一版本。

## 位置与登记

- 默认目录：项目根下 `导演项目层/`。用户已有台账目录（如 `制作台账/`）时可直接沿用，在总索引顶部登记“项目层＝某目录”，之后不再询问。
- 新工程开工时按下表建空白文件；已有项目只补缺失文件，不覆盖已有内容。

| 文件 | 内容 | 写法 |
| --- | --- | --- |
| `项目规则.md` | 作品特有的规则、用户决策、Resolved Policy、增补级别（标准/最小，见[00核心卡](00_CORE_CARD.md)）、站位记录镜（开/关，默认关，见[02C](02C_CONTINUATION_REFERENCES.md)）、画幅呼吸感（开/关，默认开，见[04](04_CAMERA_LIGHT_COLOR_STYLE.md)） | 按 08_FAST 的 A–F 分组；每条写规则和来源（用户原话、日期） |
| `lint补充.json` | 项目自己的机械检查 | `{"rules":[{"id":"…","pattern":"正则","message":"…","scope":"timeline|all"}]}` |
| `事故日志.md` | 每次返修 | 段号、用户原话、症状、根因层、改法、下一次出片是否验证 |
| `状态事件链.md` | 有跨段状态时再建：换装、受伤、湿身、污渍、道具转手 | 六列：对象｜原状态｜变化事件及位置｜新状态｜结束依据｜对应图片或缺口（见 [02A](02A_PROJECT_WORKFLOW.md)） |
| `编译卡/` | 每段编译卡 | 见 [02J](02J_SHOT_CARD.md) |

文件头第一行写 `skill-version: <写入时的 Skill 版本>`。

## 读取时机

- 开工、上下文压缩后、每段编译前：读 `项目规则.md`；已有项目里的 `误判补充.md` 继续读取，不再新建，新的写法问题直接写进 `项目规则.md`。
- 运行 `validate_prompt.py` 时用 `--project-lint <lint补充.json>` 一并检查。
- 用户退回一段或要求重做时：先在 `事故日志.md` 记一条，再修。

## 根因层（决定一条经验写到哪里）

| 根因层 | 判断 | 去处 |
| --- | --- | --- |
| skill缺规则 | 照 Skill 做了仍出错 | `项目规则.md` |
| skill有规则没执行 | 规则在，被跳过 | 不新增规则；检查编译卡和 lint 能否拦住，必要时加 `lint补充.json` |
| 模型能力限制 | 怎么写都偶发 | `项目规则.md`，附规避写法 |
| 平台限制 | 平台硬卡 | `项目规则.md` 的 F 组 |
| 项目偏好 | 只是本作品要这样 | `项目规则.md` |
| 剧本问题 | 分镜救不了 | 交编剧（[01A](01A_SCREENWRITER_HANDOFF.md)），不写进导演层 |

## 体量与兼容

- `项目规则.md` 超过约 20000 字时先合并同类条目再追加。
- Skill 升级后，若项目层某条已被新版本的核心卡或模块覆盖，提示用户删除重复条目；用户确认前照常生效。
- 项目层只影响本项目，不回写 Skill 文件。
