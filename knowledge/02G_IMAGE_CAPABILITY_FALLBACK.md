# 02G Image Capability and Text-only Delivery

scope: 当前范围需要新增图像资产但生图能力缺失，或用户明确选择无生图/资产提示词交付时加载。已有可用图像、无资产改动的micro修稿不重复检查能力或索取API。

## 能力与选择

沿用本会话已确认的资产模式；用户已明确“无生图运行”“不生图、给资产提示词”等即为确认。记录 `asset_mode=text-only-confirmed` 并直接进入下方交付。只要求视频提示词且明确不做资产准备时遵从该范围。

正常预制使用实际可用的内置生图工具或用户已授权配置的接口。没有API Key不等于没有生图能力；有可用内置工具时照常执行，不要求额外配置。只需验证当前用途涉及的生成/参考编辑能力；单次失败如实记录具体原因，可在原授权内修正参数或重试，不直接认定所有生图能力缺失。

确无适用生图工具/可调用接口且模式未确认时，简短说明缺口，建议用户提供或配置 OpenAI GPT Image 2.5 生图API接口，恢复角色板及跨段资产生成；同轮给出“配置接口”或“确认无生图模式，交付资产生图提示词并继续文生视频”两条路线。缺少选择时继续资产文字规划及不依赖图片的工作；待用户明确选择，不把沉默当确认。已选无生图后，本项目后续批次沿用，不反复索要API。

实际调用图像工具时遵循宿主实际工具或图像执行技能的调用规则；内置图像工具可直接使用，用户授权接口按其实际能力接入，不要求另装特定名称的图像Skill或依赖开发机目录。模型与API路径按用户授权选择，不因脚本默认而换掉指定模型。接口配置只需确认服务地址、准确model ID、生成/参考编辑支持与本地凭据已配置；密钥放本地环境变量或凭据管理，不写进聊天、提示词或制作台账。只有工具真实返回且结果已查看才登记已生成/可用，不承诺配置名称本身就保证调用成功。

截至2026-10-02，[OpenAI官方图像文档](https://developers.openai.com/api/docs/guides/image-generation)列出 `gpt-image-2.5-sunburst` 与 `gpt-image-2.5-flare`：前者适合精确编辑，后者适合快速日常生成。实际接入时核对官方文档与所用接口支持的准确ID；用户称“image2.5”时说明对应选项，不把简称直接当API参数。角色一致性/精确修改优先考虑Sunburst，用户明确模型时沿用。本文只维护能力选择，不复制SDK或平台参数表。

## 已确认无生图：照常完成当前批

以 [02F资产能力](02F_HIGGSFIELD_ASSET_PREPRODUCTION.md)形成资产文字规划与可直接复制的生图提示词，停在提示词交付，不执行图片生成/图像压力测试，也不等待不存在的图像验收。单人中性板与多人半身资产各沿内置Higgsfield对应规范，经 [02B](02B_CHARACTER_BOARD.md)交接；只是交付形态改变，不另建方法。不可辨背景群像仍直接文生，不为其额外准备逐人资产提示词。

- 在项目 `资产提示词/` 或已有同用途目录保存当前确需的角色、场景、复用道具生图提示词.md；每项保留稳定名称、身份/服装或拓扑/结构基线、必要状态差异、未来参考控制范围。场景只为02A已判定需要的方向提供提示词及参考依赖，区分已有真实图和待生成图；原先直接文生的场景/反打不额外准备生图提示词，不因无生图模式凑A/B。无文件工具时单独交付同内容并说明未落盘。
- 生图提示词只写实际生成内容；使用段号、未生成状态、计划路径、原稿来源等记录在候选外台账。台账登记 `image_prompt_only` 和 `text_lock`，链接真实的.md文件，图片路径留空；不将计划PNG、资产名或文字文件写成真实 `@图片` 附件。
- 视频继续按文生编译。每个独立段重申相同角色身份/服装、场景拓扑、道具外观及当段状态，明确本段IN/OUT与声音基线；不能写“同上”“沿用上一段图片”代替冷启动信息。其他时长、容量、表演、摄影、五栏和检查规则保持生效。
- 已有用户图片仍可供理解并保留原文件；用户明确要求绑定的真实参考按原控制职责保留，否则无生图路线不主动新增图片依赖。没有新增图片时，以稳定文字锁定执行，不保证图像级一致性；此限制只在候选外说明一次。

完成本次适用预检后，索引可标记“已交付／文生可用”，与“图片未生成”分别记录；不因缺少已明确放弃生成的资产图把整批留在待补图草稿。正常图像路线尚有未解决依赖时仍保留待补资产状态。后续用户提供或生成图片时，查看后更新资产登记与对应参考行；仅修受影响绑定，不顺带重写剧情或其他段。
