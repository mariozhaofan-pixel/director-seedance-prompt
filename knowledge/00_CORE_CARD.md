# 00 Core Card

priority: highest
scope: 常规新编、续段和local修复的必读执行卡；细则仍在各模块，本卡只给执行顺序、硬规则和出处。

## 一、重载与优先级

- 新会话、上下文压缩后、换集或换项目时，先重读本卡、项目层（[02K](02K_PROJECT_SLOT.md)）和本次路由文件，再继续编译；不凭对话摘要或记忆编译。
- 生效顺序：用户当场指令 > 项目层 > 本卡 > 细则模块 > 示例。项目层与本卡冲突时按项目层执行，并在台账记一行冲突说明。
- 工程模式把 Resolved Policy 写进项目层的项目规则文件；提示词-only 模式保持静默。

## 二、每段九步（一步一个产物，缺产物不进下一步）

1. **取证上一段实际成片**：联系表、切点、台词时间；写“实际结尾状态”（景别、谁在哪、朝哪、手里有什么、台词说到哪一秒）。工具：`scripts/take_evidence.py`。细则：[02C](02C_CONTINUATION_REFERENCES.md)。
2. **定衔接**：按 02C 衔接决策表选择尾段视频、前一镜带淡出或不接；项目开了站位记录镜时，改挂上一段的站位记录镜整镜视频作 `@视频1`，不截帧、不另挂尾段。
3. **过剧情门**：五问＋反应因果，见 [01A](01A_SCREENWRITER_HANDOFF.md)；不过关交编剧，不在分镜里硬补。
4. **写编译卡**：世界拓扑、逐 CUT 投影、出场、资产、动作状态，见 [02J](02J_SHOT_CARD.md)。项目模式落盘。
5. **出场与资产**：画面里看得见的每个名词对应一份素材；平台限制见 [02L](02L_PLATFORM_PROFILES.md)；工具：`scripts/check_assets.py`。
6. **写提示词**：按 SKILL.md 五栏模板；遵守项目层规则里本项目的写法补充。
7. **验证**：`scripts/validate_prompt.py`（交锋加 `validate_combat_prompt.py`）；看警告，不只看 PASS；再按 [08_FAST](08_FAST_PREFLIGHT.md) 顶部 A–F 逐条对照编译卡。
8. **交付与登记**：更新索引和台账；交付时附“镜头｜画面内容｜作用”、编译卡的方位要点、自检结论和已知风险。
9. **两段一批**：第二段标“暂定开场”；第一段出片后做差分核对，不符就在未生成前原地改，见 [02A](02A_PROJECT_WORKFLOW.md)。

## 三、十四条硬规则

| # | 规则 | 合格 | 不合格 |
| --- | --- | --- | --- |
| R1 | 续写以实际结尾为准 | 先取证再写开场状态 | 照计划结尾写开场 |
| R2 | 剧情连续就接尾段；机位拉不开时接黑场，站位写进文字（[02C](02C_CONTINUATION_REFERENCES.md)） | 换地点的追逐也接上一段尾段视频 | 只因换了地点就不接 |
| R3 | 世界坐标默认不进提示词；确需消歧时同句给出画面投影 | “镜头和CUT 2同一侧，阿某在画面左” | “阿某在西边，镜头在南边朝北” |
| R4 | 机位与背景自洽 | 机位在人物身后时，威胁在画面深处 | 机位在人物正前方，又写威胁在他身后的背景里 |
| R5 | 每个时代都有场景 | 往事和现在硬切的段，两边各有场景素材 | 只给往事场景，现在被画成空荒原 |
| R6 | 动作写成过程 | “石手一直往下伸，被挡住才停” | “石手悬在头顶”“举着不动” |
| R7 | 反应要有看得见的原因 | 先拍犯规的事，再拍群演惊呼 | 群演惊呼前没有原因 |
| R8 | 名词都有素材 | 提示词提到的人、道具、场景都挂素材 | 写了海报却没挂海报 |
| R9 | 人数写死 | “画面里只有某某一个小孩，各是各的身体” | 只写“一家人”“几个孩子” |
| R10 | 平台限制先核 | 截帧后核对宽高比、尺寸 | 上传后才被平台拒 |
| R11 | 经验沉淀在项目层 | 返修后在项目层事故日志记一条 | 只在聊天里道歉、下次重犯 |
| R12 | 体态不在切口里变；明确换了时间或空间（转场、黑屏、新场景）时可以不连续，但用一句话交代新的起始状态 | “阿某仍跪在泥里（接上一镜），撑地站起，结束时站在坑边”；“几分钟后，阿某坐在大厅角落” | 上一镜跪着，下一镜直接站着说话 |
| R13 | 同主体连续切镜要拉开 | 中景接特写，或同为近景但机位转过30°以上 | 近景直接接中景同一个人、同一个角度 |
| R14 | 站位只写在看得见的那一镜 | 每个CUT写本镜出场名单，特写写“画面里只有某某” | 开场把所有人站位写成全局声明，特写里被塞进别人 |

## 四、增补级别、摄影默认与方案沟通

- 项目层 `项目规则.md` 可设“增补级别”：`标准`（默认，按 director-expand 补表演、反应、调度）或 `最小`（只补执行必需的机位、空间、衔接与技术卫生，不新增用户没给的动作、反应、元素，等同 constrained-compile 的补足范围）。未设时按标准。增补级别同时按 `content_purpose` 静默判断并记入 Resolved Policy，不为此单独提问：默认 `narrative`，按上述增补级别执行；用户要求产品展示、汽车或商品广告且没有剧情要讲时记 `product`，该段按“最小”执行，不新增剧情转折、台词或听者反应，CUT 作用写成要看清的设计特征；剧情里夹产品镜记 `mixed`，只对产品镜所在 CUT 生效。车辆产品段写法见 [05G](05G_VEHICLE_CINEMA.md)。
- 画幅默认带克制的自然呼吸感，明确固定、极稳、站位记录镜和产品细节镜除外；项目层可写“画幅呼吸感：关”（[04](04_CAMERA_LIGHT_COLOR_STYLE.md)）。200mm 及以上一律写超大光圈、极浅景深。
- 用户明说“先给几个方案”“没想好怎么拍”时：先用三到五句复述理解（发生了什么、谁在推动、情绪从哪到哪），再给二到三个有实质差异的分镜方向（例如跟谁拍、先全貌还是先局部、落点给动作还是反应），至少一个反直觉并写明风险；选定后再编。没有这类要求时照常自主推进。
- 用户只给感觉或模糊画面（“轻松但有点不对”“像在旁边看到的”）时，分清用户已定的、自己的理解和自己的提议；原话里有意的含混和开放结局保留，不替用户定答案（“她想留他”不写成他答应留下）。

## 五、翻译规则（编译卡 → 提示词）

| 编译卡里（只给自己推算） | 写进提示词 |
| --- | --- |
| 东南西北、平面图方位、world-左右 | 画面左／中／右；前景／中景／后景（画面深处）；朝镜头／背向镜头 |
| “镜头在南边” | “镜头和CUT 2同一侧”“越过某人右肩”“在某物脚边低处仰拍” |
| 地标方位 | 看得见的地标：土坎、土路、门洞、戏台、月亮 |
| 运动方向 | “朝画面右边跑”“从画面深处朝镜头飞来” |

运镜方向词保留，再补一句读不反的证据（[04](04_CAMERA_LIGHT_COLOR_STYLE.md) 运镜方向的读不反证据）。交付前全文搜索世界方位词；`validate_prompt.py` 会给出警告，逐条删掉或在同句补出画面投影（[03](03_VISUAL_GRAMMAR_AND_SCENE_ROUTER.md) 世界拓扑与投影契约）。
