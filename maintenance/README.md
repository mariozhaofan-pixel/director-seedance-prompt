# Maintenance Files

本目录供维护者检查知识库，不属于默认运行上下文：

- `10_KNOWLEDGE_INDEX.md`：各模块字符数，以及内置功能、飞书资源和翻唱接口的入口索引。

历史验收记录保存在 Skill 目录外的维护归档中。运行规则以 `SKILL.md` 及其按需模块为准，历史测试中的旧格式和旧平台行为不覆盖当前入口。

更新运行规则后，运行 `python -B -m unittest discover -s scripts -p "test_*.py"`。涉及行为路由变化时，再按实际请求做有界前向验证。分发前核对安装包与源码的文件清单、哈希和本地引用；安装包内保留原生 Skill 结构。

## 双版本发布

后续每次发布同时交付飞书连接版与独立版。共同能力只维护一套源码；独立版通过 `editions/local-overrides.json` 移除远程工作区专用文件并替换相应入口，固定本地工作。角色板、规则反推、表情管理、编剧交接、生图能力及其降级路径在两版中保留。两版采用相同 Skill 名称与目录名，用户选择其一安装，不叠加安装。

修改被投影的入口时同步调整精确补丁；新增连接或同步路由时检查独立版处理。补丁不匹配、遗漏云路由或断链会阻止构建，不能通过关闭检查来发布。场景文生与必要方向判定统一由 `knowledge/02A_PROJECT_WORKFLOW.md` 维护；双版本差异不另设场景生成门槛。

发布步骤：

1. 完成行为验证和全套测试，更新维护索引，并刷新 `package-manifest.json` 中已审核源码的字节数与 SHA256；新增构建资源也纳入清单。
2. 在仓库外的空发布目录执行 `python -B scripts/build_editions.py --output-dir <输出目录> --version <明确版本号>`。构建器只读取清单文件，完成两版校验后输出两个 ZIP、对应 SHA256 与构建证明，不覆盖既有发布物。
3. 两版分别解压到隔离目录，运行包内测试与 Skill 入口验证；核对共同能力、独立版本地编剧交接、引用完整性及仅一个根 `SKILL.md`。运行测试不代表实际视频生成或真实飞书读写验收。
4. 交付两包并推送对应源码。维护配置、构建器、历史验收、缓存、其他平台适配包和第三方安装环境不进入安装包。

## 自动发版（2026-10-23 起）

推送 main 后，再推送形如 `YYYY-MM-DD-vN` 的标签，`.github/workflows/release.yml` 会自动跑全部测试、构建飞书版与本地版、打包 `companion-skills/director-retro`，并创建 GitHub Release 挂上 ZIP 与 SHA256；发版说明固定为“本次更新：解决了一些已知问题。”，详细记录只留在 `CHANGELOG.md`。已发布的标签不再移动，发错就发下一个版本号。构建是确定性的，同源码同版本号得到逐字节相同的 ZIP。

## 修改原则

能补充就不替换：新经验以补充条款或可选模块加入，与既有规则不冲突的写法并存；确实冲突时在更新记录写明替代了哪一条及原因。外部经验直接写进对应模块作为补充写法，不另设误判词典，也不走试用、验证流程；“跑出来不对”的症状速查统一放在 `08_MODEL_QC_REPAIR.md` 的故障修复矩阵。
