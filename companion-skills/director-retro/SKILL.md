# Director Retro

把制作中的返修变成项目层里的经验，让下一段、下一集少踩同样的坑。项目层的格式由导演 Skill 的 `knowledge/02K_PROJECT_SLOT.md` 定义；本 Skill 只负责记录、整理和提升，不改导演 Skill 的任何文件，不生成补丁，不向其他用户发送内容。

## 触发与动作

| 用户说 | 做什么 |
| --- | --- |
| 退回一段、“重做”“不行”“又错了” | 先记一条事故卡，再交给导演 Skill 修 |
| 下一段出片并被验收 | 回填上一条相关事故卡的“验证”栏：改法有效／无效 |
| “复盘一下”“这集收尾” | 生成集尾复盘：按根因层汇总，列出可提升条目，请用户逐条确认后写入项目层 |
| “项目结束” | 生成项目复盘，另附一份“可能值得进导演 Skill 下一版”的参考清单，只给维护者看 |

## 事故卡

用 `python scripts/log_incident.py --log <项目层>/事故日志.md ...` 追加，或按同样字段手写：

```text
## 2026-10-23｜第七集第08段 v1
- 用户原话：……（逐字）
- 症状：模型实际画成了什么
- 根因层：skill缺规则 / skill有规则没执行 / 模型能力限制 / 平台限制 / 项目偏好 / 剧本问题
- 改法：下一版怎么写的
- 验证：待验证 / 有效（第几版出片）/ 无效
```

也可以按 02K 写成表格，一行一条，表头含用户原话、症状、根因层、改法和验证栏（如“下次出片是否验证”）。`retro_report.py` 两种格式都能读；根因层写了说明（“平台限制（内容审核）”）也会归到对应类，验证栏写“已验证”“用户验收”都算有效。

根因层的去处照 02K 的表：只有“有效”的条目才进入提升候选；“剧本问题”交给编剧，不写进导演层；“skill有规则没执行”优先改成 lint 或编译卡检查，不新增规则。

## 集尾复盘

1. 运行 `python scripts/retro_report.py --log <项目层>/事故日志.md --out <项目层>/复盘_第X集.md`，得到按根因层分组的汇总和提升候选。
2. 对每条候选给出写法：
   - 写进 `项目规则.md` 哪一组（A–F）、原句；
   - 或写进 `lint补充.json` 的一条规则（正则、提示语、范围）。
3. 请用户逐条点头；只写被确认的条目。写入前先查重：项目层或导演 Skill 的核心卡、相关模块已有同义条目就合并，不重复追加。
4. 把当集台账里仍通用的条目移到项目层，当集台账只留分段计划、资产台账和本集特例。

## 项目复盘与发版参考

在集尾复盘之外，额外列出满足以下全部条件的条目，标题写“供维护者参考”：

- 不含具体作品的人名、地名、道具名（改写成通用说法）；
- 在两个以上场景复现，或一次严重且改法已验证有效；
- 与导演 Skill 现有规则不冲突，或写明替代哪一条。

是否并入导演 Skill 由维护者在正常发版时决定；本 Skill 不改动导演 Skill。

## 边界

- 只读写项目目录；不碰任何 Skill 安装目录。
- 用户原话逐字记录；不替用户补写或美化。
- 不确定根因层时标“待定”，在复盘时请用户判断。
